# Проверка стандартов и практик редактора LikeC4

**Актуальная область приёмки изменена пользователем 5 октября 2026: только desktop-сервис создания диаграмм.**
Root AGENTS.md фиксирует эту policy. Mobile, WCAG/AT и accessibility certification исключены из обязательного
цикла; их результаты ниже сохранены как исторический аудит, а не текущие delivery blockers.
Актуальный рабочий документ: [DESKTOP-CHECKLIST.md](DESKTOP-CHECKLIST.md). ST01 keyboard persistence остаётся
desktop дефектом и закрывается новой browser проверкой. ST02, обязательность ST03 по WCAG и mobile ST04
выведены из scope; desktop placement проверяется как дополнительное удобство. Desktop performance проверяется
отдельно, mobile evidence для него не используется. Исключение проверки из scope не означает PASS.

Дата проверки: 5 октября 2026. Объект: приватный браузерный редактор `apps/gui-to-code`, основной UI на русском языке.

**Результат: частичное соответствие. Полное соответствие WCAG 2.2 AA, прохождение Core Web Vitals и релизная готовность не подтверждены.** Расширенная проверка выявила четыре незакрытых пункта. Прежние 355 app tests и 51 browser scenarios подтверждают свою матрицу; они не покрывают новые stress scenarios.

Чек-лист заполнен для всех **83 пунктов**: 55 официальных критериев WCAG 2.2 уровня A/AA и 28 инженерных проверок. Результаты: **26 PASS, 24 PARTIAL, 4 FAIL, 14 NOT_RUN, 15 N/A**. Это число проверок, а не процент качества продукта. Машиночитаемая версия: [checklist.json](evidence/standards/checklist.json).

## Правила оценки

- **PASS** — конкретная проверка пройдена с указанным evidence и scope; этот статус не является отдельным сертификатом WCAG.
- **PARTIAL** — часть требования проверена, существенная часть остаётся непроверенной либо ограниченной.
- **FAIL** — указанная проверка не выполнена приложением или обнаружено отсутствие необходимой функции.
- **NOT_RUN** — проверка не выполнялась; наличие кода или теста само по себе не заменяет результат.
- **N/A** — требование неприменимо к текущим функциям редактора; причина записана в строке. При расширении продукта применимость пересматривается.

Основание WCAG — [официальный текст W3C](https://www.w3.org/TR/WCAG22/). Полное AA требует выполнения всех применимых A и AA, включая полные процессы; [условия conformance](https://www.w3.org/TR/WCAG22/#conformance-reqs). Каталог из 55 критериев получен из официального текста, исключает AAA и удалённый 4.1.1. Первичные passages: [wcag-criteria.json](evidence/standards/wcag-criteria.json).

Performance thresholds взяты из [Core Web Vitals](https://web.dev/articles/vitals): LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1, при оценке реальных пользователей на 75-м перцентиле отдельно для mobile/desktop. Наш cold lab sample служит диагностикой, **не field certification**. Другие инженерные пункты — явно выбранные best practices и контракты [SPEC](../../SPEC.md), а не утверждение о прохождении ISO/OWASP сертификации.

## Подтверждённые практики

EditorWorkspace остаётся единственным semantic/history owner; candidate проходит compiler/semantic verification до commit. Source-preserving patches сохраняют неизменённые свойства и комментарии. Atomic history, last valid canvas, CAS conflict и backup recovery подтверждены owner и browser tests. ZIP имеет bounded validation.

Sanitizer применяется до HTML rendering. В отдельной Chrome модели `script`, event handler и `javascript:` link не выполнились: marker=false, dangerous elements=0, link href=null. [Browser proof](evidence/standards/markdown-browser.json), [27 owner tests](evidence/standards/markdown-tests.log). Это проверка конкретных payloads, не полный аудит безопасности.

На 320 CSS px основная оболочка и пустой inspector не требуют горизонтальной прокрутки; close control доступен. [Geometry](evidence/standards/viewport-320.json). Text-spacing overrides прошли для шести основных controls document shell; ShadowRoot и все dialogs требуют отдельного прохода. [Probe](evidence/standards/text-spacing.json).

## Критерий завершения следующего цикла

- ST01–ST04 исправлены и повторены на новом frozen JS/CSS; новые regressions добавлены в owner/browser suite.
- Все применимые PARTIAL/NOT_RUN имеют выполненную проверку либо обоснованное изменение применимости; формальный AA claim допускается только после закрытия всей нормативной матрицы и полных процессов.
- CI проверяет тот же опубликованный candidate; scoped lint/formatting не заменяют полный gate.
- Real device/AT matrix и human onboarding имеют фактические результаты. Production TLS/headers и dependency review относятся к реальному deployment.
- Performance claim опирается на размерно разделённые lab measurements и отдельно на field p75. Выбранные профили и product budgets явно названы, не выданы за универсальный стандарт.

До выполнения этих условий редактор имеет подтверждённые практики в ограниченном scope и незакрытые требования. Полное соответствие стандартам остаётся неподтверждённым.
