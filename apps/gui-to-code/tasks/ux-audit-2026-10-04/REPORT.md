# Аудит пользовательского пути визуального редактора LikeC4

Исторический аудит до исправлений. Итог повторных циклов и актуальная локальная проверка: [CORRECTIONS.md](CORRECTIONS.md).

Проверка от 4 октября 2026 года через Chrome DevTools MCP. Главный вывод: базовый путь создания модели работает, но редактор пока нельзя считать надёжным для сохранения пользовательской архитектуры. Изменение названия может удалить описание, а холст с ручной раскладкой может показывать уже удалённые сущности. Сначала нужно устранить эти две ошибки, затем восстановить согласованность выделения, истории и обратной связи.

Документ содержит воспроизведение проблем, границы доказательств и последовательный план исправления. Изменения продукта не выполнялись.

## Объект проверки и доказательства

Проверялся `apps/gui-to-code` на [локальном preview](http://127.0.0.1:4174/). Использованы отдельный профиль Chrome и изолированные контексты с искусственными моделями. Размеры окна: 1280 × 720, широкое окно 1440 × 801 и мобильная эмуляция 390 × 844. Это проверка Chrome на macOS; мобильная эмуляция не заменяет реальное устройство.

Рабочая копия содержит ранее сделанные изменения. HEAD: `7cedbbe182f834a8a589ef6e84535cf76301f4a7`. Отданный браузеру `index-DyG7wbpp.js` совпал с файлом в локальном `dist`: SHA256 `453daec8cb926c048ef9be8c57c98481c52ca69dc165d41c847e83176cec6f52`, 4 687 759 байт. Это идентичность проверенного артефакта, а не подтверждение, что все текущие исходники вошли в сборку.

В [папке evidence](evidence/) сохранены снимки интерфейса, воспроизведение потери описания, настоящий экспорт .c4 и ZIP и результаты Lighthouse. Lighthouse accessibility: **84/100**. Оценка относится к одному состоянию страницы и не доказывает доступность всего редактора. Размер JS измерен; задержки запуска на медленной сети не измерялись.

Поиск по MCP графу был предпринят, но проект не индексирован. Владельцы кода установлены чтением файлов. Привязки к исходникам ниже объясняют найденное поведение и задают область исправления; точную причину исключения при обновлении раскладки ещё предстоит установить.

Для загрузки тестовых файлов MCP не разрешил путь native upload. Файлы подавались через настоящий file input с `File/DataTransfer`, затем выполнялся штатный обработчик импорта и подтверждение замены. Проверена логика приложения, а не работа системного выбора файла. Экспорт наблюдался на уровне реального Blob без отмены штатного скачивания; открытие файла из папки Downloads отдельно не проверялось.

Последовательность успешных операций для dynamic/deployment сохранена в [отдельном снимке](evidence/12-dynamic-deployment.txt). Защита конкурентной записи — в [снимке конфликта](evidence/10-conflict.txt).

## Ошибки функциональности

### Потеря и невозможность сохранить описание

**F01 · P1 · подтверждено в браузере.** Импортировать компонент с `description 'Обрабатывает заказы'`, выбрать его, изменить только название и сохранить. Описание видно в карточке и её AX имени, но поле инспектора пустое. После сохранения названия описание исчезает из исходника; редактор сообщает об успешном сохранении. Отдельное добавление описания на другом компоненте завершается «Не удалось подтвердить новые свойства элемента».

[Потеря данных](evidence/11-description-loss.txt), [описание отдельно](evidence/03-description-only.txt), [отказ формы](evidence/02-inspector-rejection.txt).

В [use-semantic-editor.ts](../../src/editor/use-semantic-editor.ts) описание принимается только как string. Модель также использует объекты txt/md. В [workspace.ts](../../src/editor/workspace.ts), около строки 1514, сравнивается объект модели со строкой patch. [element-form.ts](../../src/editor/ui/element-form.ts) отправляет все поля и превращает пустое описание в null. Вместе это объясняет очищение неизменённого свойства и отказ подтверждения новой строки.

**Решение:** единое преобразование MarkdownOrString для чтения и проверки, с использованием существующего `flattenMarkdownOrString`. Patch содержит только реально изменённые поля. Неизменённое описание не нормализуется и не переписывается.

### Холст показывает удалённые данные и старые подписи

**F02 · P1 · подтверждено в браузере.** Создать компонент, связать его с Customer, задать подпись связи, сохранить и перезагрузить. В исходнике подпись есть, на ручном холсте её нет; в экспортированном snapshot label остаётся null. Затем удалить компонент с подтверждённой входящей связью. Исходник удаляет оба объекта, статус подтверждает успех, но холст продолжает показывать компонент и связь со старым названием.

[Удалённый объект на холсте](evidence/09-deleted-ghost.txt), [снимок устаревшей связи](evidence/04-stale-edge.png), [экспорт исходника](evidence/export.c4), [ZIP с раскладкой](evidence/export.zip).

В той же ручной раскладке наблюдались наложение нового узла на существующий и конец стрелки в пустом пространстве. Это проявления проблемы размещения и согласования геометрии; отдельная причина наложения пока не установлена.

**Решение:** текущая валидная модель определяет существование узлов, связи и подписи. Snapshot сохраняет совместимую геометрию через существующие drift/autoapply механизмы. Удалённые объекты не должны возвращаться из snapshot; изменение названия не требует ручного подтверждения. Для новых узлов — безопасное размещение с проверкой наложений. Не вводить второй граф или свой формат координат.

### Обновление ручной раскладки завершается без понятного результата

**F03 · P2 · подтверждено в браузере.** Открыть Compare с `edges-drift / label-added`, нажать Apply changes. Сравнение закрывается, подпись не обновляется. В консоли появляется `applyLatestToManual onError`, доступная сериализация ошибки — `{}`; пользователь не получает объяснения и следующего действия.

[Состояние перед применением](evidence/05-layout-drift.txt). В [state.sync-queue.ts](../../../../packages/diagram/src/editor/actor/state.sync-queue.ts), около строки 221, обработчик пишет ошибку в console и очищает очередь. В [useEditorActorLogic.ts](../../../../packages/diagram/src/editor/useEditorActorLogic.ts) вызывается существующий `applyChangesToManualLayout`. Место и причина исключения ещё не доказаны.

**Решение:** удерживать сравнение открытым при ошибке, показывать русскую причину и повтор/просмотр авторасладки; не выдавать успешное завершение. Сброс ручной раскладки — отдельное явное действие с объяснением потери размещения.

### Отказ от смены элемента не возвращает выделение на холсте

**F04 · P2 · подтверждено в браузере.** Изменить поля API, щёлкнуть Customer, попытаться сохранить, получить отказ и выбрать «Остаться». Инспектор и быстрые действия относятся к API, а подсветка и панель стилей renderer — к Customer.

**Решение:** запрашивать смену выделения через общий guard до её принятия. После «Остаться» возвращать canvas selection и фокус к прежнему объекту; после «Отбросить» переключать все производные поверхности вместе. Владельцы: [App.tsx](../../src/App.tsx), semantic/canvas hooks и существующий selection contract.

### Статус сохранения скрывает несохранённую форму

**F05 · P2 · подтверждено в браузере.** Изменить свойства и получить отказ сохранения. Глобально продолжает отображаться «Рабочее пространство сохранено», рядом может оставаться предыдущий успешный результат. После перезагрузки несохранённые поля формы потеряны.

Фактически сохранённая ревизия и локальная форма — разные состояния, но интерфейс этого не объясняет. В исходниках приложения не найден beforeunload. Наличие или отсутствие системного подтверждения выхода не выводится из автоматической навигации MCP.

**Решение:** отдельно показывать «Изменения в свойствах не сохранены» и состояние сохранённой ревизии; убирать устаревшее сообщение успеха при новом действии. Пока форма dirty, предупреждать о выходе/перезагрузке. Не сохранять невалидную форму как валидную ревизию.

### Enter на выбранном узле не выполняет обещанное действие

**F06 · P2 · подтверждено дважды, включая активную вкладку.** Выбрать узел на холсте и нажать Enter. Подсказка обещает свойства, но инспектор остаётся закрытым. F2 запускает изменение названия, Delete открывает удаление. Enter на элементе структуры работает. AX описание узла сообщает «Keyboard activation is disabled».

**Решение:** согласовать renderer и [editor-shortcuts.ts](../../src/editor/editor-shortcuts.ts). Enter на выбранном узле открывает свойства и переводит фокус в форму, при этом Enter в полях, меню, диалогах и IME сохраняет своё обычное действие. Учитывать Shadow DOM и composedPath.

### Redo и возврат выбирают служебный вид

**F07 · P2 · подтверждено в браузере.** Из пустой модели создать первый элемент и `view1`, отменить название и создание, повторить создание. Выбирается `Landscape view (index)`, хотя в исходнике есть только authored `view1`. Перезагрузка воспроизводит выбор служебного index.

[Снимок Redo](evidence/08-bootstrap-redo.txt). [view-selection.ts](../../src/editor/ui/view-selection.ts) предпочитает id index без учёта происхождения. [workspace.ts](../../src/editor/workspace.ts) уже различает служебный index и вид с source provenance.

**Решение:** сохранять существующий активный authored вид; при восстановлении без него выбирать первый authored вид, служебный index — последний fallback. Явный пользовательский index остаётся полноценным видом.

### Устаревшая выбранная связь остаётся доступной для действия

**F08 · P2 · подтверждено в браузере.** После Undo/Redo выбранная связь остаётся в быстрых действиях. Удаление получает «Рабочее пространство или текущий вид изменились. Выберите связь заново».

Защита ревизии работает и предотвращает неверную запись. Дефект в том, что интерфейс предлагает заведомо устаревшее действие.

**Решение:** после изменения ревизии обновлять идентичность выбранной сущности по существующим правилам либо явно снимать выделение и закрывать устаревшую форму. Не ослаблять expectedRevision guard.

До включения этих контролов в обещания продукта нужно либо провести полноценное изменение и проверку сохранения, либо скрыть их. Это не отдельный доказанный browser defect.

## План исправлений

Приоритет P1 означает потерю данных или неверное представление архитектуры. P2 — нарушение рабочего пути, доступности или доверия к состоянию. P3 — улучшение ясности без блокировки операции.

Порядок: **сохранность свойств → актуальный холст → выделение и история → старт и виды → компоновка → доступность и язык**. Ниже шесть пакетов с владельцами на уровне модулей. Назначение конкретных разработчиков требует владельца проекта; аудит его не придумывает.

## Инварианты и границы реализации

- Единственный mutable semantic/history owner остаётся EditorWorkspace. UI и compiled model — производные текущей валидной ревизии.
- Источники нескольких файлов, комментарии и форматирование сохраняются при incremental edits. Whole-document DSL generation остаётся явной нормализацией/экспортом.
- Геометрия принадлежит diagram и стандартным `.likec4/<view>.likec4.snap`. Семантика не берётся из старой геометрии.
- Compile failure не заменяет last valid revision. CAS, backup и экспорт при конфликте сохраняются.
- Пакеты выше — предложения аудита, они не меняют managed ROADMAP.STATUS и не объявляют WP ready. Перед реализацией владелец связывает выбранный пакет с существующим WP/AC, проверяет зависимости и ограничивает write scope согласно scoped AGENTS.md.
- Изменения public core/diagram требуют focused tests и patch changeset. Для отчёта и private приложения changeset не нужен. После изменения core exports/declarations выполнить `pnpm exec tsc --build` до downstream typecheck; при изменении grammar/style presets выполнить `pnpm generate`.
- Если сохранение геометрии и семантики требует новой политики для неоднозначного drift, зафиксировать её отдельно перед расширением автоматического применения. Нельзя закрывать F02 маскировкой призраков только в UI.
