# Проверка фокуса — 6 октября 2026

Авторизация: прямой запрос пользователя проверить наложение рамки на подпись «Название» и похожие случаи.
Это ограниченное исправление отображения в рамках WP-16; критерии AC-08/AC-10.
Write scope этого прохода: `src/style.css`, этот отчёт и локальные browser evidence.
Workspace, DSL, compiler, history и persistence не изменялись этим исправлением.
Стоп-условие: воспроизведение исходного дефекта, исправление общих правил и browser readback похожих контролов.
Изменение семантических владельцев или публичного API потребовало бы отдельного scope.

## Причина и исправление

В CanvasCreateMenu подпись и поле находились в обычном label без промежутка.
Рамка шириной 2 px с наружным offset 2 px занимала ещё 4 px вокруг поля и заходила на подпись.
Такая рамка также неудобна для плотных кнопок, строк дерева и прокручиваемых контейнеров.

- Общая рамка фокуса и рамка file-upload label размещаются внутри границы контрола: offset −2 px.
- Labels с прямым input/select/textarea имеют grid и промежуток 8 px, включая меню создания вне form.
- Маленькие checkbox сохраняют наружную рамку; существующий промежуток до текста сохранён.
- В обновлённом составном выборе технологии рамка принадлежит общей оболочке, также внутри границы;
  промежуток до подписи — 8 px. Внутренний input не получает второй рамки.

В браузере исходный случай воспроизведён до изменения. После исправления геометрический промежуток
между текстом подписи и полем — около 9.8 px, рамка полностью остаётся внутри поля.
Tab переводит фокус на «Создать и связать», Shift+Tab возвращает в поле.

## Проверка в Chromium

На отдельной неизменяемой production-копии проверено **122 состояния фокуса**.
Часть контролов повторяется в разных пользовательских состояниях; это не число уникальных элементов.

| Состояния                                     | Проверок |
| --------------------------------------------- | -------: |
| Верхняя панель и инструменты холста           |       12 |
| Создание вида, включая дополнительные поля    |        6 |
| Создать и связать                             |        5 |
| Структура, поиск, collapse/visibility/locking |       12 |
| Inline-название                               |        3 |
| Инспектор элемента и составная технология     |       10 |
| Создание динамического/ deployment вида       |        9 |
| Теги                                          |        2 |
| Диалог удаления                               |        3 |
| Исходники, поиск файла и редактор кода        |        5 |
| Файловое меню                                 |        5 |
| Быстрое меню холста                           |        5 |
| Dynamic-step controls и его инспектор         |       14 |
| Deployment controls и инспектор связи         |       22 |
| Логическая связь и форма её создания          |        9 |

Проверены реальные computed styles при видимом фокусе: 2 px, offset −2 px и 8 px у подписей полей.
Для составной технологии проверяется оболочка; для checkbox — его отдельная рамка.
File-upload оболочка проверена дополнительно через focus скрытого file input.
Просмотрены скриншоты до/после и панелей. Технология выбрана через UI; её фокус остаётся видимым.
Dynamic/deployment/ logical edge inspectors для этой проверки открыты browser click event на SVG edge;
проверяемые поля получают реальный DOM focus. Это проверка отображения, а не новая приёмка pointer routing.

## Остальные проверки и границы

- Первый проход: app tests 465/465, generate, types и production build прошли.
- Existing production browser regressions: 14/14 — connected creation, Undo/Redo,
  inspector, native dialogs, Tab/Shift+Tab, menu dismissal и inline naming.
- После параллельных изменений редактора: UI tests 182/182, повторные generate/build и итоговый typecheck прошли.
- Agent instruction checks 10/10, format check и diff check прошли.

Во время этого прохода другой процесс менял инспектор, меню и сборку в общем checkout.
Поэтому результаты исходного полного app/browser прогона и последующей проверки фокуса относятся
к своим сборкам и не объединяются в утверждение о полной приёмке всех параллельных изменений.
Проверка ограничена Chromium desktop и перечисленными состояниями.
