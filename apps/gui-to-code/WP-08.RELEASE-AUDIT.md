## Architecture invariants

- `EditorWorkspace` remains the sole owner of committed semantic state.
- LikeC4 DSL sources and standard manual-layout snapshots remain canonical persisted data.
- Compiled models, canvas nodes, diagnostics, selection, dialogs and focus remain derived or transient.
- UI components do not construct DSL directly.
- WP-08 does not add a second semantic graph, persistence schema, state-management framework or DSL family.

## Discovery inventory to complete

### User-visible strings

Audit buttons, labels, dialogs, placeholders, status text, errors, tooltips, empty states, confirmations and import/export notifications. English is allowed only for DSL keywords, identifiers, file extensions and established technology names.

### Interactive surfaces

Audit toolbar actions, menus, dialogs, form controls, selectors, tree/source controls, canvas actions, draggable nodes, file inputs and destructive confirmations.

### Acceptance coverage

Map Playwright and focused tests to logical editing, relations, static views, layouts, dynamic workflows, deployment workflows, durable recovery, `.c4` import/export and ZIP import/export. Record gaps for keyboard, focus restoration, Escape, busy guards, live regions, narrow/wide viewports and production artifact smoke.

### CI release path

Verify the real production build output and serve command, then extend the existing GUI-to-code workflow rather than creating a temporary workflow. Required evidence must refer to the exact PR head.

## Decision gates

Stop scope expansion and document an interface proposal if a fix requires a public owning-package API, persistence schema migration, semantic-state ownership change, package-boundary change or major dependency.

## Review records

The final pull request body must contain separate evidence-backed sections for:

- correctness and reliability review;
- product, accessibility and release review.

All P0/P1 findings must be resolved before the PR is marked ready for review.
